# 일일 자동 운영 지침 (스케줄 루틴이 매일 읽고 따르는 문서)

목표: **AI 업무자동화 키트**의 판매를 만든다. 매일 검색 유입용 글 1편과 SNS 초안을 쌓고,
판매 데이터를 기록하고, 주 1회 전략을 점검한다.

## 0. 준비
1. 저장소 `seungyun-shin/Agent_work_reposi` 를 받아 운영 브랜치를 체크아웃한다
   (운영 브랜치 이름은 루틴 프롬프트에 적혀 있다). 최신 상태로 pull 한다.
2. `docs/assets/config.js`의 `checkoutUrl`이 비어 있으면 아직 결제 링크가 없는 상태다.
   콘텐츠 작업은 그대로 하되, 리포트 맨 위에 "결제 링크 미설정"을 적는다.

## 1. 판매 기록
`python3 automation/sales_report.py` 를 실행한다. 출력 결과를 리포트에 그대로 옮긴다.
토큰이 없거나 API가 실패하면 실패했다고 적는다. **판매 수치를 추정하거나 지어내지 않는다.**

## 2. 블로그 글 1편
1. `automation/content_calendar.md` 에서 체크되지 않은 첫 항목을 고른다.
2. `automation/posts/YYYY-MM-DD-<slug>.md` 로 원고를 쓴다. 기존 글 3편의 형식을 따른다:
   - 머리 메타데이터: title / description / date / slug (slug는 영문 소문자·하이픈)
   - 제목에 메인 키워드, 첫 문단에 독자의 문제와 해결책
   - H2 소제목 4~6개, 표 또는 체크리스트 1개 이상, 1,800~2,500자, 끝에 요약
   - **복붙용 프롬프트는 1개만** 공개한다 (키트 판매를 해치지 않도록). 키트 원문을 통째로 옮기지 않는다
   - 관련된 기존 글로 내부 링크 1~2개 (`slug.html`)
3. 굵게 표시가 따옴표·괄호에 붙어 한글과 이어지면 `**` 대신 `<strong>`을 쓴다.
4. `python3 automation/build_site.py` 를 실행해 에러 없이 끝나는지 확인한다.
5. 캘린더 항목을 `[x] MM-DD slug` 로 바꾼다.

## 3. SNS 초안
`automation/sns/YYYY-MM-DD.md` 에 오늘 글을 바탕으로 아래를 쓴다. 사용자가 복사해 올린다.
- 스레드/X: 첫 줄 후킹 + 5~7줄 + 글 링크 (`https://seungyun-shin.github.io/Agent_work_reposi/blog/<slug>.html`)
- 인스타그램 캐러셀: 슬라이드 6장 텍스트 + 캡션 + 해시태그 10개
- 숏폼 30초 대본: | 시간 | 화면 | 자막 | 표
홍보 비율은 정보 4 : 홍보 1. 매일 판매 링크를 넣지 않는다 (5일에 1번 꼴로 키트 소개).

## 4. 주간 점검 (월요일에만)
`automation/reports/YYYY-Www.md` 에 지난 7일을 정리한다.
- 판매 건수·매출 (metrics.csv 기준), 발행 글 수
- 가설 1개와 이번 주 실험 1개 (예: 가격 문구, 랜딩 헤드라인, 주제 방향)
- 실험이 사이트 문구 변경이면 직접 반영하고, 가격·상품 자체 변경은 **사용자에게 제안만** 한다.

## 5. 커밋 & 푸시
`git add automation docs && git commit` (메시지: `운영: MM-DD 글 <slug>`) 후 운영 브랜치로 push.
네트워크 오류면 2·4·8·16초 간격으로 최대 4번 재시도.

## 절대 하지 않는 것
- 가짜 후기, 가짜 구매 수, 근거 없는 "1위·최고·100%" 같은 과장 문구
- 실존 인물·회사 사칭, 타인 콘텐츠 복제
- 키트 PDF 원문 전체 공개, 비밀 토큰 커밋
- 사용자 계정으로 무단 게시·댓글·DM (SNS 게시는 사용자가 하거나, 사용자가 연결한 도구로만)
- 결제·가격·환불 정책 변경 (제안만 가능)

## 마무리 출력
마지막 메시지로 5줄 이내 리포트: 판매 현황 / 오늘 발행한 글 / SNS 초안 파일 / 이슈 / 사용자가 할 일(있으면).
